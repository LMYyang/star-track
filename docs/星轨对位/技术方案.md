# 星轨对位（对称空间）技术方案

> 版本：v1.0（2026-11-23）
> 前置阅读：[需求文档](./星轨对位-需求文档.md)，**§3.3 判定规则是本方案唯一实现基线**
> 原则：完全复用《顶牛子》工程骨架（uni-app H5 + Vue3 + Vitest + `server/` 单端口托管 + esbuild 单文件打包），新增独立玩法模块，不侵入、不复制其牌局业务代码。

---

## 1. 方案结论（先读）

| 决策点 | 结论 | 理由 |
|---|---|---|
| 仓库形态 | **新建独立仓库 `D:\demo\star-track`**，从顶牛子复制工程骨架 | 与《阶梯密码》同一思路：新玩法独立演进，顶牛子零风险；后续想合库也只需搬 `src/pages/star` 与 `src/core/star` |
| 运行位置 | **单人玩法 100% 前端**，判定不走服务器 | 无对手、无排行榜时没有作弊面；答案本来就在本地，上服务器只增加一次往返与一套状态机 |
| 渲染方式 | **DOM(view) 绝对定位，不用 canvas** | 最多 81 个格点 + 40 个星点 + 40 条线，DOM 足够；canvas 在 uni-app 的 H5/小程序接口、DPR、导出差异是纯成本 |
| 真相来源 | **关卡数据只存 `sources`**，`targets` 运行时由对称群推导 | 避免「数据里的答案」与「代码里的答案」两份真相；CI 断言两者一致 |
| 判定接口 | 对 UI 只暴露 `{ pass, deviations }` | 从接口层保证「不提示具体哪个点错」；坐标数组只在 core 内部与提示系统用 |
| 服务端 | 保留 `server/index.js` 的「静态托管 + ws」骨架，P0 无业务消息 | 部署方式与顶牛子完全一致：`dist/ + server/` 两个目录，一条 `node` 命令 |
| 关卡数量 | 64 关（10 章），已随文档交付并通过全量校验 | v1.1 追加第 8~10 章：四重旋转、暗域禁落、综合终章；后续用生成器/编辑器扩 |

### 2.2 本方案沿用的关键机制

| 机制 | 顶牛子的做法 | 星轨对位怎么用 |
|---|---|---|
| 纯核心 + 组合层 | `src/core/*` 不依赖 Vue / uni，`composables` 只做状态与视图同步 | 完全照搬：`src/core/star` 可在 Node 里直接跑 |
| 自定义导航 | 全部页面 `navigationStyle: custom`，页面自绘返回键 | 沿用，保证深空背景不被系统导航栏切断 |

| 测试隔离 | Vitest 不加载 uni 插件，只测 `tests/**/*.test.js` | 沿用；所有判定/关卡逻辑必须能脱离 uni 运行 |

- `server/rooms.js`（4 座位、骨牌 AI、骰子编排）——不复制；P2 竞速另写 `starRooms.js`。
- `src/core/game.js / rules.js / ai.js / deck.js`——与本玩法无关。
- `src/components/PlayingTile.vue / HandArea.vue` 等——牌面渲染与星点无关。

### 3.2 精简后的 `server/index.js`（可直接用）

保留顶牛子的骨架能力（静态托管、SPA 回退、64KB 帧上限、15s 心跳），删掉所有业务分支：

```js
// server/index.js —— 星轨对位：静态托管 + 预留 ws
import { createServer } from 'node:http'
import { promises as fs } from 'node:fs'
import path from 'node:path'
import { fileURLToPath } from 'node:url'
import { WebSocketServer } from 'ws'
import { readPort } from './port.js'

const HEARTBEAT_MS = 15_000

export function createServerApp(port = readPort(), { heartbeatMs = HEARTBEAT_MS } = {}) {
  const staticDir = process.env.STATIC_DIR
    ? path.resolve(process.env.STATIC_DIR)
    : path.resolve(path.dirname(fileURLToPath(import.meta.url)), '../dist/build/h5')

  let staticReady = null
  const httpServer = createServer(async (req, res) => {
    try {
      const url = new URL(req.url, 'http://localhost')
      let pathname = decodeURIComponent(url.pathname)
      if (pathname.includes('..')) { res.writeHead(403).end(); return }
      if (pathname === '/') pathname = '/index.html'
      const file = path.join(staticDir, pathname)
      if (!file.startsWith(staticDir)) { res.writeHead(403).end(); return }

      staticReady ||= fs.readdir(staticDir).then(() => true, () => false)
      if (!(await staticReady)) { res.writeHead(426).end('WebSocket only'); return }

      const data = await fs.readFile(file).catch(() => null)
      if (data === null) {
        const index = await fs.readFile(path.join(staticDir, 'index.html')).catch(() => null)
        if (index === null) { res.writeHead(404).end('Not Found'); return }
        res.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' }).end(index)
        return
      }
      const ext = path.extname(file).toLowerCase()
      const types = {
        '.html': 'text/html; charset=utf-8', '.js': 'text/javascript; charset=utf-8',
        '.css': 'text/css; charset=utf-8', '.json': 'application/json',
        '.svg': 'image/svg+xml', '.png': 'image/png', '.woff2': 'font/woff2',
        '.mp3': 'audio/mpeg', '.wav': 'audio/wav',
      }
      res.writeHead(200, { 'Content-Type': types[ext] || 'application/octet-stream' }).end(data)
    } catch (e) {
      console.error('[server] static error:', e.message)
      res.writeHead(500).end()
    }
  })

  const wss = new WebSocketServer({ server: httpServer, maxPayload: 64 * 1024 })

  wss.on('connection', (socket) => {
    const conn = {
      raw: socket, alive: true, token: null,
      send(obj) { if (socket.readyState === socket.OPEN) socket.send(JSON.stringify(obj)) },
    }
    socket.on('error', (err) => console.error('[server] socket error:', err.message))
    socket.on('pong', () => { conn.alive = true })
    socket.on('message', () => { conn.alive = true })

    const beat = setInterval(() => {
      if (socket.readyState !== socket.OPEN) { clearInterval(beat); return }
      if (!conn.alive) { clearInterval(beat); socket.terminate(); return }
      conn.alive = false
      try { socket.ping() } catch { /* 下一轮再判 */ }
    }, heartbeatMs)
    beat.unref?.()

    socket.on('close', () => clearInterval(beat))
    socket.on('message', (raw) => {
      let msg
      try { msg = JSON.parse(raw.toString()) } catch {
        return conn.send({ type: 'error', payload: { code: 'BAD_JSON', message: '消息格式错误' } })
      }
      // P0 只有探活；P2 在这里挂 star.* 路由（§8）
      if (msg?.type === 'ping') conn.send({ type: 'pong', payload: {} })
    })
  })

  return { httpServer, wss, port }
}
```

启动文件（同顶牛子）：


## 5. 核心纯逻辑（`src/core/star`）

### 5.1 `symmetry.js` —— 唯一的数学实现

设计要点：

1. **轴位一律换算成「半格整数」**（`hx = 2 × axis`），彻底消除 `2.5` 这类浮点在 `2a - x` 里的误差。
2. 斜轴的 `c` 只接受整数，否则像会落在半格上（加载时抛出，校验器提前拦截）。
3. 轴格只由「整格轴」产生；缝轴没有轴格。

```js
// src/core/star/symmetry.js
// 坐标 (x,y)：x 向右、y 向下，0..N-1。所有轴位以「半格整数」参与运算。

const DIR_VEC = { U: [0, -1], R: [1, 0], D: [0, 1], L: [-1, 0] }
const VEC_DIR = new Map(Object.entries(DIR_VEC).map(([k, v]) => [v.join(','), k]))

export const DIR_KEYS = ['U', 'R', 'D', 'L']

/** 原始 sym → 归一化 sym。非法参数直接抛错（关卡校验器会先捕获） */
export function normalizeSym(raw) {
  const half = (v, name) => {
    const n = Number(v)
    if (!Number.isFinite(n)) throw new Error(`${name} 非法: ${v}`)
    const h = Math.round(n * 2)
    if (Math.abs(n * 2 - h) > 1e-9) throw new Error(`${name} 必须是整数或半整数: ${v}`)
    return h
  }
  const t = raw?.type
  switch (t) {
    case 'v': return { type: 'v', hx: half(raw.axis, 'axis') }
    case 'h': return { type: 'h', hy: half(raw.axis, 'axis') }
    case 'p': return { type: 'p', hx: half(raw.cx, 'cx'), hy: half(raw.cy, 'cy') }
    case 'cross': return { type: 'cross', hx: half(raw.ax, 'ax'), hy: half(raw.ay, 'ay') }
    case 'd1':
    case 'd2':
      if (!Number.isInteger(raw.c)) throw new Error(`斜轴 c 必须是整数: ${raw.c}`)
      return { type: t, c: raw.c }
    case 'r': {
      // 四重旋转：中心必须落在格点或格心，否则格点会转到半格上
      const hx = half(raw.cx, 'cx')
      const hy = half(raw.cy, 'cy')
      if ((hx + hy) % 2 !== 0) throw new Error(`旋转中心必须落在格点或格心: (${raw.cx}, ${raw.cy})`)
      return { type: 'r', hx, hy }
    }
    default:
      throw new Error(`未知对称类型: ${t}`)
  }
}

export function keyOf(p) {
  return p.length === 3 ? `${p[0]},${p[1]},${p[2]}` : `${p[0]},${p[1]}`
}

/** 群元素：用仿射矩阵表示 `x' = a·x + b·y + tx`，`y' = c·x + d·y + ty`；
 *  方向用同一个线性部分 (a,b,c,d) 变换，位移 (tx,ty) 不影响方向。 */
const M = (a, b, c, d, tx, ty) => ({ a, b, c, d, tx, ty })

export function groupOf(sym) {
  switch (sym.type) {
    case 'v': return [M(1, 0, 0, 1, 0, 0), M(-1, 0, 0, 1, sym.hx, 0)]
    case 'h': return [M(1, 0, 0, 1, 0, 0), M(1, 0, 0, -1, 0, sym.hy)]
    case 'p': return [M(1, 0, 0, 1, 0, 0), M(-1, 0, 0, -1, sym.hx, sym.hy)]
    case 'd1': return [M(1, 0, 0, 1, 0, 0), M(0, 1, 1, 0, -sym.c, sym.c)]
    case 'd2': return [M(1, 0, 0, 1, 0, 0), M(0, -1, -1, 0, sym.c, sym.c)]
    case 'cross': return [
      M(1, 0, 0, 1, 0, 0),
      M(-1, 0, 0, 1, sym.hx, 0),
      M(1, 0, 0, -1, 0, sym.hy),
      M(-1, 0, 0, -1, sym.hx, sym.hy),
    ]
    case 'r': {
      // C4：屏幕 y 向下，顺时针 90° 即 (dx,dy) → (−dy,dx)
      const s = (sym.hx + sym.hy) / 2   // 两个平移分量在「半格整数」下必为整数
      const d = (sym.hy - sym.hx) / 2
      return [
        M(1, 0, 0, 1, 0, 0),
        M(0, -1, 1, 0, s, d),           // 90°
        M(-1, 0, 0, -1, sym.hx, sym.hy),// 180°
        M(0, 1, -1, 0, -d, s),          // 270°
      ]
    }
    default: throw new Error(`groupOf 不支持: ${sym.type}`)
  }
}

export function applyMat(m, p) {
  return [m.a * p[0] + m.b * p[1] + m.tx, m.c * p[0] + m.d * p[1] + m.ty]
}

export function applyDir(m, d) {
  const [dx, dy] = DIR_VEC[d]
  const k = VEC_DIR.get(`${m.a * dx + m.b * dy},${m.c * dx + m.d * dy}`)
  if (!k) throw new Error(`方向映射失败: ${d}`)
  return k
}

/** 群阶：单轴/中心 k=2；双轴/四重旋转 k=4 */
export function groupOrder(sym) {
  return ['cross', 'r'].includes(sym.type) ? 4 : 2
}

/** 全部像（含自身），顺序与 groupOf 一致 */
export function groupImages(sym, p) {
  return groupOf(sym).map((m) => applyMat(m, p))
}

/** 单个镜像（翻折预览、残星陷阱校验用）。
 *  cross 取「竖+横」复合像（第 4 个元素），r 取顺时针 90°；仅用于「看着可镜像」的校验，不参与判定。 */
export function imageOf(sym, p) {
  const elems = groupOf(sym)
  const m = sym.type === 'cross' ? elems[3] : elems[1]
  return applyMat(m, p)
}

/** 单轴的方向变换；cross 请用 `applyDir(groupOf(sym)[i], d)` 逐元素算 */
export function dirImage(sym, d) {
  return applyDir(groupOf(sym)[1], d)
}

/** 轴格集合（整格轴才有；缝轴返回空集） */
export function axisCells(sym, n) {
  const cells = new Set()
  const push = (x, y) => { if (x >= 0 && x < n && y >= 0 && y < n) cells.add(`${x},${y}`) }

  if (sym.type === 'v' && sym.hx % 2 === 0) for (let y = 0; y < n; y++) push(sym.hx / 2, y)
  if (sym.type === 'h' && sym.hy % 2 === 0) for (let x = 0; x < n; x++) push(x, sym.hy / 2)
  if (sym.type === 'p' && sym.hx % 2 === 0 && sym.hy % 2 === 0) push(sym.hx / 2, sym.hy / 2)
  if (sym.type === 'cross') {
    if (sym.hx % 2 === 0) for (let y = 0; y < n; y++) push(sym.hx / 2, y)
    if (sym.hy % 2 === 0) for (let x = 0; x < n; x++) push(x, sym.hy / 2)
  }
  if (sym.type === 'd1') for (let x = 0; x < n; x++) push(x, x + sym.c)
  if (sym.type === 'd2') for (let x = 0; x < n; x++) push(x, sym.c - x)
  // 旋转中心在格点上时，中心格是唯一不动点，视同轴格
  if (sym.type === 'r' && sym.hx % 2 === 0 && sym.hy % 2 === 0) push(sym.hx / 2, sym.hy / 2)

  return cells
}

```

**数学自检（必须写进单测）**

- 对合性：任意类型、任意合法点，`image(image(p)) === p`。
- 整数封闭：任意合法参数下，像仍是整数（这依赖「半格整数」与「斜轴 c 整数」两条约束）。
- 群封闭：`cross` 的 4 个像再作用仍是这 4 个像（集合不变）。
- 轴格不动点：整格轴上的点，像是它自己；因此关卡数据禁止把源点放在轴格上。
- **旋转不是对合**：`r` 作用两次是 180°，四次才回到原位；`imageOf` 对 `r` 取 90° 像，所以「对合性」测试只覆盖镜像类，`r` 单独测 `g4 = e`、四像互异与整数封闭。

### 5.2 `judge.js` —— 唯一的判定实现

```js
// src/core/star/judge.js
import { groupOf, applyMat, applyDir, keyOf } from './symmetry.js'

/**
 * 推导目标集：Map<key, { p, src }>
 * 规则（需求 §3.3）：
 *  - 每个源点取群作用全部像，去掉自身；
 *  - 越界 / 轴格 / 与其它像重复 → 非法关卡（校验器拦截，运行时也抛错）；
 *  - 箭头关的像带方向（逐个群元素用 applyDir 变换；`cross` 的四个像分属 v/h/180，
 *    方向可能两两相同，必须逐元素算而不能只算一次）。
 */
export function deriveTargets(level, sym) {
  const map = new Map()
  const n = level.board
  const axis = level.axisCells // Set<string>，由 levels.js 注入
  for (const s of level.sources) {
    for (const m of groupOf(sym)) {
      const q = applyMat(m, s)
      if (q[0] === s[0] && q[1] === s[1]) continue
      if (q[0] < 0 || q[0] >= n || q[1] < 0 || q[1] >= n) {
        throw new Error(`关卡 ${level.id}: 源点 ${keyOf(s)} 的像越界 ${keyOf(q)}`)
      }
      if (axis.has(keyOf(q))) {
        throw new Error(`关卡 ${level.id}: 源点 ${keyOf(s)} 的像落在轴格 ${keyOf(q)}`)
      }
      const p = level.arrows ? [q[0], q[1], applyDir(m, s[2])] : [q[0], q[1]]
      const k = keyOf(p)
      if (!map.has(k)) map.set(k, { p, src: s })
    }
  }
  return map
}

/**
 * 判定：P 必须与 T 严格相等。
 * 返回 missing / extra 供提示系统使用；UI 只能看 pass + deviations。
 */
export function judge(targets, placed) {
  const pl = new Map(placed.map((p) => [keyOf(p), p]))
  const missing = []
  const extra = []
  for (const [k, v] of targets) if (!pl.has(k)) missing.push(v)
  for (const [k, p] of pl) if (!targets.has(k)) extra.push(p)
  return {
    pass: missing.length === 0 && extra.length === 0,
    deviations: missing.length + extra.length,
    missing,
    extra,
  }
}

/** 给 UI 的安全视图：只有布尔与数量 */
export function judgeForUi(targets, placed) {
  const r = judge(targets, placed)
  return { pass: r.pass, deviations: r.deviations }
}
```

要点：

- **复杂度**：`O(|S|·k + |P|)`，≤ 40 个点，微秒级。
- **严禁**在 `judge` 里做「容差距离」比较：一律 `key` 字符串相等，杜绝浮点误差与「差不多算过」。
- 目标集在 `levels.js` 里**加载时算一次并缓存**，游戏中不再重算（64 关 × 小集合，内存可忽略）。

```js
  return 1
}

/** 顺序解锁：第 1 关永久解锁；第 n 关要求 cleared >= n-1 */
export function isUnlocked(progress, no) {

}
```

### 5.4 `progress.js` —— 持久化

```js
// src/core/star/progress.js
const KEY = 'startrack_progress_v1'

export function emptyProgress() {
  return { v: 1, cleared: 0, stars: {}, records: {} }
}

function normalize(p) {
  if (!p || typeof p !== 'object') return emptyProgress()
  return {
    v: 1,
    cleared: Number.isInteger(p.cleared) ? p.cleared : 0,
    stars: p.stars && typeof p.stars === 'object' ? p.stars : {},
    records: p.records && typeof p.records === 'object' ? p.records : {},
  }
}

export function loadProgress(store = uni) {
  try { return normalize(store.getStorageSync(KEY)) } catch { return emptyProgress() }
}

export function saveProgress(p, store = uni) {
  try { store.setStorageSync(KEY, p) } catch { /* 隐私模式：静默降级 */ }
}

export function clearProgress(store = uni) {
  try { store.removeStorageSync(KEY) } catch { /* noop */ }
}

/** 通关写入：只升不降 */
export function recordWin(progress, levelNo, { star, movesUsed, timeMs }) {
  const p = normalize(progress)
  p.stars[levelNo] = Math.max(p.stars[levelNo] || 0, star)
  if (levelNo > p.cleared) p.cleared = levelNo
  const rec = p.records[levelNo] || {}
  p.records[levelNo] = {
    star: p.stars[levelNo],
    bestMoves: Math.min(rec.bestMoves ?? Infinity, movesUsed),
    bestTimeMs: Math.min(rec.bestTimeMs ?? Infinity, timeMs),
    tries: (rec.tries || 0) + 1,
  }
  return p
}

export function totalStars(progress) {
  return Object.values(progress?.stars || {}).reduce((a, b) => a + b, 0)
}
```

```js
// src/core/star/hint.js
/** 提示优先级：先补缺点，缺点为空则指出一个多余点（需求 §3.7） */
export function pickHint(result, rng = Math.random) {
  if (result.missing.length) {
    return { kind: 'missing', ...result.missing[Math.floor(rng() * result.missing.length)] }
  }
  if (result.extra.length) {
    return { kind: 'extra', p: result.extra[Math.floor(rng() * result.extra.length)] }
  }
  return null
}
```

### 5.6 v1.1 扩展：暗域禁落格与装配期约束

新增机制只加在「数据 + 装配 + UI」三处，判定接口 judge(targets, placed) 一行没动：

1. **数据**：关卡多一个可选字段 blocked: [[x,y], ...]（0~6 格）。装配时生成两个派生字段：blockedList（给渲染）与 blockedCells（Set，给落点与推导查表）。
2. **推导**：deriveTargets 在「越界 / 轴格」之外多了三条拒绝：像落在暗域、像与任一源点重合、以及不动点（旋转中心格）直接跳过。任何一条命中都在加载期抛错，由校验器汇总成全量错误清单。
3. **容量**：freeCells = board² − axisCells.size − blockedCells.size，必须装得下「源点 + 目标」，否则判无解。
4. **箭头唯一位置**：箭头关若两个目标同格异向，玩家物理上补不出来；装配期直接判错。
5. **交互**：点击暗域格返回 { ok:false, reason:'BLOCKED' }，页面顶部轻提示「暗域里落不下星」，与轴格的提示文案区分；不扣失误、不计提交。
6. **渲染**：暗域格用径向近黑的暗斑 + 紫色虚线边框 + 中心暗核；旋转中心用金色虚线圆环 + 三枚曳光点（14s 自转），不画轴线。

> 兼容性：老 40 关不含 blocked，字段缺省为空数组，装配与判定行为与 v1 完全一致；黄金快照重生成后 1~40 关目标集逐关不变（已核对）。

### 6.3 校验器 `scripts/validate-levels.mjs`

**每次 `npm test` 前置执行**（`pretest`），任何一关不合法直接让构建红掉。

```js
// scripts/validate-levels.mjs
import fs from 'node:fs'
import path from 'node:path'
import { fileURLToPath } from 'node:url'
import { normalizeSym, axisCells, keyOf, groupOf, applyMat, applyDir, imageOf, groupOrder, DIR_KEYS } from '../src/core/star/symmetry.js'

const ROOT = path.resolve(path.dirname(fileURLToPath(import.meta.url)), '..')
const data = JSON.parse(fs.readFileSync(path.join(ROOT, 'src/core/star/levels.data.json'), 'utf8'))

const errs = []
const fail = (id, msg) => errs.push(`[L${id}] ${msg}`)

const BOARD_OK = new Set([5, 7, 9])

data.levels.forEach((l, i) => {
  if (l.id !== i + 1) fail(l.id, `id 不连续：期望 ${i + 1}`)
  if (!BOARD_OK.has(l.board)) fail(l.id, `board 非法 ${l.board}`)
  if (l.chapter < 1 || l.chapter > 7) fail(l.id, `chapter 非法 ${l.chapter}`)
  if (!(l.moves >= 1)) fail(l.id, `moves 非法 ${l.moves}`)
  if (![1, 2].includes(l.hints)) fail(l.id, `hints 非法 ${l.hints}`)
  if (l.arrows !== l.sources.every((s) => s.length === 3)) fail(l.id, 'arrows 与 sources 结构不一致')
  if (l.arrows && !l.sources.every((s) => DIR_KEYS.includes(s[2]))) fail(l.id, '存在非法方向')

  let sym
  try { sym = normalizeSym(l.sym) } catch (e) { return fail(l.id, e.message) }
  const axis = axisCells(sym, l.board)
  const n = l.board

  const srcKeys = new Set()
  for (const s of l.sources) {
    if (s[0] < 0 || s[0] >= n || s[1] < 0 || s[1] >= n) fail(l.id, `源点越界 ${keyOf(s)}`)
    if (axis.has(keyOf(s))) fail(l.id, `源点在轴格 ${keyOf(s)}`)
    if (srcKeys.has(keyOf(s))) fail(l.id, `源点重复 ${keyOf(s)}`)
    srcKeys.add(keyOf(s))
  }

  const tgt = new Map()
  for (const s of l.sources) {
    for (const m of groupOf(sym)) {
      const q = applyMat(m, s)
      if (q[0] === s[0] && q[1] === s[1]) continue
      if (q[0] < 0 || q[0] >= n || q[1] < 0 || q[1] >= n) { fail(l.id, `像越界 ${keyOf(q)}`); continue }
      if (axis.has(keyOf(q))) { fail(l.id, `像落轴格 ${keyOf(q)}`); continue }
      const p = l.arrows ? [q[0], q[1], applyDir(m, s[2])] : [q[0], q[1]]
      const k = keyOf(p)
      if (tgt.has(k)) fail(l.id, `像重复 ${k}`)
      tgt.set(k, p)
    }
  }
  for (const [k] of tgt) if (srcKeys.has(k)) fail(l.id, `目标与源点重合 ${k}`)

  const expect = l.sources.length * (groupOrder(sym) - 1)
  if (tgt.size !== expect) fail(l.id, `目标数 ${tgt.size} ≠ 期望 ${expect}`)
  if (l.targetCount !== tgt.size) fail(l.id, `targetCount 字段 ${l.targetCount} ≠ 推导 ${tgt.size}`)

  for (const d of l.strays) {
    if (srcKeys.has(keyOf(d))) fail(l.id, `残星与源点重合 ${keyOf(d)}`)
    if (tgt.has(keyOf(d))) fail(l.id, `残星与目标重合 ${keyOf(d)}`)
    const q = imageOf(sym, d)
    if (!q || q[0] < 0 || q[0] >= n || q[1] < 0 || q[1] >= n) fail(l.id, `残星不构成陷阱（镜像越界）${keyOf(d)}`)
    else if (tgt.has(keyOf(q))) fail(l.id, `残星不构成陷阱（镜像落在目标上）${keyOf(d)}`)
  }

  // 可放置空格必须留出余量，避免「唯一空位」伪难度
  const empty = n * n - axis.size - srcKeys.size - l.strays.length
  if (empty < tgt.size + 2) fail(l.id, `可放置空格不足：${empty} < ${tgt.size + 2}`)
})

if (errs.length) {
  console.error(`关卡校验失败 ${errs.length} 条：\n` + errs.join('\n'))
  process.exit(1)
}
console.log(`关卡校验通过：${data.levels.length} 关`)
```

### 7.2 画板几何：一份 `layout()` 同时供渲染与命中

```js
// 逻辑坐标 → 像素：格点位于 (pad + x*step, pad + y*step)
export function layoutOf(sizePx, n) {
  const pad = Math.round(sizePx * 0.06)          // 6% 内边距：边缘星点不贴边，好点
  const step = (sizePx - pad * 2) / (n - 1)
  return {
    sizePx, pad, step,
    at: (x, y) => [pad + x * step, pad + y * step],
  }
}
```

- 星域是正方形：`sizePx = min(可视宽 - 32px, 可视高 - 顶部HUD - 底部操作条)`，在 `onReady` 与 `onResize`（H5 旋转/窗口缩放）时重算。
- **渲染与命中共用同一个 `layout` 对象**，这是防「看着点在格上、点不中」的唯一办法。

### 7.3 命中测试与手势

```js
// 触点 → 格点索引；超出 0.6 格距视为点空（需求 §3.2）
export function hitTest(localX, localY, geo, n) {
  const gx = Math.round((localX - geo.pad) / geo.step)
  const gy = Math.round((localY - geo.pad) / geo.step)
  if (gx < 0 || gx >= n || gy < 0 || gy >= n) return null
  const [px, py] = geo.at(gx, gy)
  if (Math.hypot(localX - px, localY - py) > geo.step * 0.6) return null
  return [gx, gy]
}
```

取触点的双通道（H5 与小程序都要过）：

```js
function pointFromEvent(e) {
  const t = e.changedTouches?.[0] || e.touches?.[0]
  if (t && typeof t.clientX === 'number') return { x: t.clientX, y: t.clientY }
  if (e.detail && typeof e.detail.x === 'number') return { x: e.detail.x, y: e.detail.y }
  return null
}
```

- 画板 `id="star-board"`，用 `uni.createSelectorQuery().in(instance).select('#star-board').boundingClientRect()` 取 `left/top`，缓存到 `boardRect`；`onResize` 与页面 `onShow` 重取。
- 事件绑定：`@tap="onTap"`、`@longpress="onLong"`（`view` 原生支持，H5/小程序一致；不要用 `touchstart` 自己算长按，会和滚动冲突）。
- 逻辑像素 vs rpx：**所有几何计算用 px**（`boundingClientRect` 返回 px）；样式里的字号/间距用 `rpx`。两者只在 `pad/step` 边界处相遇，绝不混算。

### 7.5 渲染细节

- **网格点**：`N*N` 个 8rpx 圆点，绝对定位；用 `v-for` 一次性生成，`key = `${x},${y}``。
- **轴线**：用「一像素矩形 + rotate」画，不用 SVG：
  ```js
  function lineStyle(x1, y1, x2, y2) {
    const len = Math.hypot(x2 - x1, y2 - y1)
    return {
      left: `${x1}px`, top: `${y1}px`, width: `${len}px`, height: '2px',
      transform: `rotate(${Math.atan2(y2 - y1, x2 - x1)}rad)`,
      transformOrigin: 'left center',
    }
  }
  ```
  端点计算（`P = geo.pad`，`S = geo.step`）：
  - `v`：`(P + (hx/2)*S, P) → (P + (hx/2)*S, P + (n-1)*S)`
  - `h`：`(P, P + (hy/2)*S) → (P + (n-1)*S, P + (hy/2)*S)`
  - `d1`（`y = x + c`）：`x` 从 `max(0, -c)` 到 `min(n-1, n-1-c)`，对应 `(P+x*S, P+(x+c)*S)`
  - `d2`（`x + y = c`）：`x` 从 `max(0, c-(n-1))` 到 `min(n-1, c)`，对应 `(P+x*S, P+(c-x)*S)`
  - `p` / `cross`：两条正交轴线（竖 + 横），中心画一个 12rpx 的星核圆点（整格中心时）
- **轴格**：只用 `axisCells` 集合判断，命中为真则画「星尘轨」空心十字，并在 `celltap` 时直接拦截（不进 composable）。
- **源点**：实心 `#EAF6FF` + 24rpx 辉光 + 四芒（两条细线交叉）；`animation: breathe 3s infinite`。
- **残星**：空心环（`border: 1rpx solid #6B7280`，`background: transparent`）+ 5s 漂移 2rpx；**形状差异**是主通道，颜色是辅通道。
- **玩家点**：实心暖白 + 蓝色外环；落点 `scale(0.4) → 1` 的 120ms 弹入。
- **箭头**：星点 + 一条 10rpx 的尾线，整体按 `U/R/D/L` 旋转（`U: -90deg, R: 0, D: 90deg, L: 180deg`）。一格只有一个图元，方向是它的属性。

### 7.6 连线动画（通关表现）

```js
function linkOf(src, tgt, geo) {
  const [x1, y1] = geo.at(src[0], src[1])
  const [x2, y2] = geo.at(tgt[0], tgt[1])
  return { x1, y1, x2, y2, len: Math.hypot(x2 - x1, y2 - y1), angle: Math.atan2(y2 - y1, x2 - x1) }
}
```

- 每条线一个 `view`：`width: len`、`height: 1px`、`transform: rotate(angle) scaleX(0)`，`transition: transform 260ms`，`transition-delay: i*80ms`，下一帧改 `scaleX(1)`。
- 最多 15 对（双轴 15 个目标），远低于性能阈值；> 30 条时降级为「整体淡入 400ms」，不做逐条。
- 线段只存在于动画层，**不参与命中**（`pointer-events: none`）。

### 7.7 `useStar.js` —— 单局状态机

```js
// src/composables/useStar.js（节选，完整实现按此结构展开）
import { reactive, computed } from 'vue'
import { levelOf, starOf } from '../core/star/levels.js'
import { judge, judgeForUi } from '../core/star/judge.js'
import { pickHint } from '../core/star/hint.js'
import { loadProgress, saveProgress, recordWin } from '../core/star/progress.js'

export function useStar(no) {
  const level = levelOf(no)
  const state = reactive({
    phase: 'PLAYING',        // PLAYING | CHECKING | WON | FAILED
    placed: [],              // [x,y] 或 [x,y,dir]
    dir: 'U',                // 箭头关当前方向
    mistakes: 0,
    movesLeft: level.moves,
    hintsLeft: level.hints,
    hintsUsed: 0,
    ghost: null,             // { p, src, kind }
    startedAt: Date.now(),
    elapsedMs: 0,
    result: null,            // judgeForUi 的结果快照
    guideResult: null,       // 顶部提示条的文案数据（偏差数或 null）
  })

  function canPlace(p) { /* 轴格、已占用、越界 → false */ }
  function tapCell(p) { /* 已占用则移除；空则 push；phase !== PLAYING 直接 return */ }
  function cycleDir(p) { /* 已有箭头顺时针；空则用 state.dir 落点 */ }
  function undo() { state.placed.pop() }
  function clear() { state.placed = [] }
  function useHint() { /* pickHint(result) → state.ghost，hintsLeft-- */ }
  function submit() { /* 见下 */ }
  function retry() { /* 重置 placed/mistakes/hints/moves/timer，level 不变 */ }

  return { level, state, tapCell, cycleDir, undo, clear, useHint, submit, retry }
}
```

**`submit()` 的精确顺序（必须照此实现）**

```js
function submit() {
  if (state.phase !== 'PLAYING' || state.placed.length === 0) return null

  state.phase = 'CHECKING'
  const ui = judgeForUi(level.targets, state.placed)    // 对外只用这个
  state.movesLeft -= 1

  setTimeout(() => {
    state.result = ui
    if (ui.pass) {
      state.phase = 'WON'
      const star = starOf({ mistakes: state.mistakes, hintsUsed: state.hintsUsed })
      const p = recordWin(loadProgress(), level.id, {
        star, movesUsed: level.moves - state.movesLeft, timeMs: state.elapsedMs,
      })
      saveProgress(p)
    } else {
      state.mistakes += 1
      state.phase = state.movesLeft <= 0 ? 'FAILED' : 'PLAYING'
      // 注意：失败后回到 PLAYING，玩家可继续修改已有点再提交
    }
    state.guideResult = ui.pass ? null : { deviations: ui.deviations }
  }, 400)
  return ui
}
```

要点：

- `CHECKING` 的 400ms 内**锁死全部输入**（按钮 disabled + 画板 `disabled`），防连点重复提交扣次数。
- 失败（还有次数）回到 `PLAYING` 且**保留玩家点**，这是「自己纠错」的核心体验；不要清空。
- 通关写进度用 `recordWin`，星级只升不降。
- 计时：`setInterval(1000)` 更新 `elapsedMs`；`onHide` 记下时间戳，`onShow` 补差，页面卸载 `clearInterval`。

## 8. 服务端（P0 零业务；P2 两种玩法）

### 8.1 为什么单人不上服务器

- 单人模式的「答案」是关卡数据，本来就在客户端包里；上服务器不能保护任何东西。
- 判定是纯函数，客户端与服务端必然算出同一结果；上服务器只多一次往返与一套会话状态。
- 结论：**单人 = 纯前端 `useStar` 状态机**；`server/` 只负责把 `dist/build/h5` 托管出去（顺便复用顶牛子成熟的部署链路）。

### 8.2 P2 每日挑战（服务端权威）

| 方向 | type | payload | 说明 |
|---|---|---|---|
| C→S | `star.daily.get` | `{ date? }` | 取当日题（服务端按日期派生，禁止客户端指定关卡） |
| S→C | `star.daily.state` | `{ date, level, attemptsLeft }` | `level` 只含 `sources/strays/sym/board`，**不含 targets** |
| C→S | `star.daily.submit` | `{ date, placement, moves, timeMs }` | 服务端重新推导 targets 并判定 |
| S→C | `star.daily.result` | `{ pass, deviations, star, rank }` | 失败只给偏差数（服务端也不下发坐标） |
| C→S | `star.daily.rank` | `{ date }` | 前 50 名（昵称 + 用时 + 星） |

- 服务端必须 **import `src/core/star/*`**（esbuild 已把 `src/core` 内联进 bundle，天然可用）。
- 防作弊：客户端提交 `placement` 与 `moves/timeMs`，服务端用自己的 targets 判；客户端上报的 `pass` 一律忽略。
- 每日题派生：`seed = hash(date)`，从 64 关里选一关（或按 seed 生成，见 §13）。

### 8.3 P2 双人竞速

| 方向 | type | payload | 说明 |
|---|---|---|---|
| C→S | `star.room.create` / `join` / `leave` / `ready` | 同顶牛子房间语义 | 2 座位 |
| S→C | `star.room.state` | `{ room }` | 房间快照 |
| C→S | `star.race.start` | `{}` | 双方 ready 后房主开赛 |
| S→C | `star.race.state` | `{ levelId, startAt, phase }` | 双方同一关、同一 `startAt` |
| C→S | `star.race.submit` | `{ placement, moves }` | 服务端判定；**首次通过即锁定胜者** |
| S→C | `star.race.result` | `{ winnerToken, pass, deviations, timeMs }` | 双方收到同一结果 |

复用顶牛子 `rooms.js` 的成熟机制（不复制业务）：

| 机制 | 复用方式 |
|---|---|
| token 会话 + `tokens` Map | 照抄 |
| 60s 断线宽限 + `gone` 标记 | 照抄（`GRACE_MS = 60_000`） |
| 30s sweep 清理 5min 空房 | 照抄（`ROOM_IDLE_MS = 5 * 60_000`） |
| 15s 心跳 / 64KB 帧上限 | 已在精简版 `server/index.js` 保留 |
| `findMemberByConn` 防幽灵成员 | 照抄 |
| 结算确认与超时 | 简化为 2 人版（先到者胜，无平局） |

> 竞速的公平性关键：**同一关、同一 `startAt`、服务端判定**。客户端只负责画，不负责裁决。

### 9.2 性质测试（防数学回归）

```js
import { describe, it, expect } from 'vitest'
import { normalizeSym, imageOf, groupImages, groupOf, applyDir, DIR_KEYS } from '../src/core/star/symmetry.js'

const dirTable = (raw, i = 1) => DIR_KEYS.map((d) => applyDir(groupOf(normalizeSym(raw))[i], d))

const SYMS = [
  { type: 'v', axis: 2 }, { type: 'v', axis: 2.5 },
  { type: 'h', axis: 3 }, { type: 'h', axis: 3.5 },
  { type: 'd1', c: 0 }, { type: 'd1', c: 2 },
  { type: 'd2', c: 6 }, { type: 'd2', c: 4 },
  { type: 'p', cx: 3, cy: 3 }, { type: 'p', cx: 3.5, cy: 3.5 },
  { type: 'cross', ax: 3, ay: 3 }, { type: 'cross', ax: 3.5, ay: 2.5 },
]

describe('symmetry 性质', () => {
  it('两次翻折回到原点（对合）', () => {
    for (const raw of SYMS) {
      const sym = normalizeSym(raw)
      for (let x = 0; x < 9; x++) for (let y = 0; y < 9; y++) {
        const p = [x, y]
        const q = imageOf(sym, p)
        expect(imageOf(sym, q)).toEqual(p)
      }
    }
  })

  it('像是整数（不允许半格）', () => {
    for (const raw of SYMS) {
      const sym = normalizeSym(raw)
      for (let x = 0; x < 9; x++) for (let y = 0; y < 9; y++) {
        const q = imageOf(sym, [x, y])
        expect(Number.isInteger(q[0]) && Number.isInteger(q[1])).toBe(true)
      }
    }
  })

  it('cross 的像集合是 4 元且封闭', () => {
    const sym = normalizeSym({ type: 'cross', ax: 3, ay: 3 })
    const set = new Set(groupImages(sym, [1, 2]).map((p) => p.join(',')))
    expect(set.size).toBe(4)
    for (const q of groupImages(sym, [1, 2])) {
      expect(new Set(groupImages(sym, q).map((p) => p.join(',')))).toEqual(set)
    }
  })

  it('方向表与需求 §3.10 一致', () => {
    expect(dirTable({ type: 'v', axis: 3 })).toEqual(['U', 'L', 'D', 'R'])
    expect(dirTable({ type: 'h', axis: 3 })).toEqual(['D', 'R', 'U', 'L'])
    expect(dirTable({ type: 'd1', c: 0 })).toEqual(['L', 'D', 'R', 'U'])
    expect(dirTable({ type: 'd2', c: 6 })).toEqual(['R', 'U', 'L', 'D'])
    expect(dirTable({ type: 'p', cx: 3, cy: 3 })).toEqual(['D', 'L', 'U', 'R'])
    // cross 的四元素方向各不相同：id / 竖 / 横 / 双翻
    expect(dirTable({ type: 'cross', ax: 3, ay: 3 }, 1)).toEqual(['U', 'L', 'D', 'R'])
    expect(dirTable({ type: 'cross', ax: 3, ay: 3 }, 2)).toEqual(['D', 'R', 'U', 'L'])
    expect(dirTable({ type: 'cross', ax: 3, ay: 3 }, 3)).toEqual(['D', 'L', 'U', 'R'])
  })
})
```

> 注意方向表断言用 `DIR_KEYS = ['U','R','D','L']` 的顺序；写实现时不要改动这个顺序，否则表会错位。

| 判定耗时 | < 1ms | `console.time` + 单测 1e4 次循环 |
| 渲染节点 | ≤ 130（81 格点 + 6 轴线/轴格 + 40 星点 + 15 线） | DevTools Elements 计数 |
| 首屏 JS（gzip） | ≤ 120KB | uni H5 默认包体 + 无新增依赖 |
| 关卡 JSON | ≤ 40KB | 当前 64 关约 35KB |
| 音频 | ≤ 3MB | 只留 1 首 bgm + 5 个短音效 |

> 不引入任何第三方动画/图形库；线条、星点、辉光全部用 `view + CSS`。

### 10.4 兼容

| 端 | 状态 | 备注 |
|---|---|---|
| H5（Safari / Chrome / 微信内置） | 首发 | 主目标 |
| 微信小程序 | 可随框架出包 | 不用 canvas；`@longpress` 与 `boundingClientRect` 均支持；`rpx` 已适配 |

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 斜轴 `c` 写成半整数 | 像落半格，判定永远不可能通过 | `normalizeSym` 直接抛错 + 校验器拦截 + 单测覆盖 |
| 缝轴 `2.5` 浮点误差 | 偶发「差 1 格」 | 轴位一律 `hx = 2a` 整数运算；JSON 里的 `2.5` 只在入口转一次 |
| 渲染与命中共用两套几何 | 看着对准却点不中 | 只有一个 `layout()`，`StarBoard` 内部持有，渲染/命中共用 |
| 残星只靠亮度区分 | 色弱用户无法识别；小屏看不出 | 形状差异（空心环）+ 颜色 + 长按标签三重冗余 |
| 关卡数据与判定两份真相 | 改数据不改代码 → 判定错 | 数据只存 `sources`；`targets` 运行时推导；`pretest` 校验 `targetCount` |
| 关卡构图为手工采样，未必每关都「星座感」 | 观感一般 | 交付前跑 `preview-levels.mjs` 人工校形；只调 `sources`/`blocked`，不动判定 |
| 双轴关目标 15 个、提交上限 4 次 | 偏难，可能劝退 | 数据可热改：`moves` 调到 5~6；先用真机 10 人小样本测 |
| 连线动画在低端机掉帧 | 通关瞬间卡顿 | ≤ 15 条逐条动画；> 30 条降级整体淡入；`will-change: transform` |
| 长按与页面滚动冲突 | 手势误触 | `game` 页 `disableScroll` + 画板 `touchmove.stop.prevent`；用原生 `longpress` 不用自算 |
| 小程序 `rpx` 与 px 混算 | 布局错位 | 逻辑全 px，样式全 rpx，二者只在 `layout()` 输出处交汇 |
| 微信小程序包体超限 | 无法发布 | 音频只留 1 首 bgm（或首发不带 bgm），关卡 JSON 9.5KB |

## 13. 落地顺序（照着做即可）

1. 建仓库、复制骨架、精简 `server/index.js`（§3）。
2. 先写 `symmetry.js` + `star-symmetry.test.js`，**测试先绿**（数学不过，后面全是白干）。
3. 写 `judge.js` + `judge.test.js`，用 §6.2 四个基准关跑黄金用例。
4. 放 `levels.v2.json`（本方案附带 64 关），写 `levels.js` + 校验脚本，`npm test` 前先校验。
5. 写 `progress.js / hint.js`，测试覆盖星级边界与存储兜底。
6. 做 `StarBoard.vue`：先只画网格 + 轴线 + 源点，用固定 `layout` 手动验命中。
7. 接 `useStar.js`：落点 → 撤销 → 提交 → 失败保留点 → 通关写进度。
8. 做星图册与解锁，再补提示 / 引导 / 连线 / 音效。
9. `build:h5` + `build:server`，单端口起服务，真机回归。
10. 内容打磨：`preview-levels.mjs` 逐关看图，必要时只改 `sources/moves`。
