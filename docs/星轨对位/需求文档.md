# 星轨对位（对称空间）需求文档

> 版本：v1.0（2026-11-23）
> 定位：单人闯关的空间对称解谜。给一条对称轴与轴一侧的星点，玩家在另一侧补星，使整体满足指定对称关系。
> 关联文档：[技术方案](./星轨对位-技术方案.md) ｜ 关卡数据：`星轨对位-关卡数据-v2.json`（64 关 / 10 章，已全量校验）
> 工程基座：复用《顶牛子》uni-app + Vue3 + Vitest + `server/` 单端口托管框架（详见技术方案 §1–§2）

---

## 1. 游戏概述

### 1.1 一句话描述

星域里有一条发光的对称轴，轴一侧已经摆好若干星点，玩家在另一侧补点；提交时系统只回答「对齐」或「存在偏差」，玩家靠脑内翻折把整幅星图补成严格对称。

### 1.2 玩法定位

| 维度 | 说明 |
|---|---|
| 类型 | 益智 / 空间想象（非对抗、非数值、非文字） |
| 人数 | 单人（首期）；双人竞速为 P2 |
| 单关时长 | 教学关 1~2 分钟；常规关 3~6 分钟；高阶关 5~8 分钟 |
| 目标用户 | 8 岁以上，无需任何几何知识；也适合成人做空间训练 |
| 平台 | H5 首发（uni-app），后续可出微信小程序 |
| 核心体验 | 脑内翻折 → 落点 → 无定位反馈 → 自我纠错 |
| 与《顶牛子》关系 | 独立玩法模块，共用工程骨架、部署链路、音效库；不共用任何牌局核心 |

### 1.3 三条设计支柱

1. **可校验的几何**：判定是纯坐标映射与集合比较，没有随机、没有概率、没有主观评分。任何一关都能用一段脚本证明「唯一解存在」。
2. **反馈克制**：失败只说「有偏差」（高阶连偏差数量都不给），逼迫玩家自己在脑中复核，而不是靠试错穷举。
3. **难度靠结构而非数量**：竖轴 → 横轴 → 45° 斜轴 → 中心 → 双轴 → 干扰点 → 箭头方向 → 四重旋转 → 暗域禁落 → 综合，十章逐层加一个「新的空间维度」，而不是单纯堆星点。

### 1.4 与常见「对称拼图」的区别

- 常见的镜像拼图是**拖拽整块图形**，系统帮你算翻折；本玩法要求**逐点自己算翻折**，翻折运算本身才是玩法。
- 常见的解谜失败会给「哪一块错了」的高亮；本玩法**关闭定位信息通道**，只留一个布尔结果，纠错成本由玩家承担。
- 轴线不总是竖直：45° 斜轴、中心对称、双轴十字会改变「坐标怎么变」，玩家每章都要重建一次心理模型。

## 2. 术语与坐标系（判定基石）

### 2.1 星域（画板）

- 星域是一个 **N×N 的格点阵**，N ∈ {5, 7, 9}，即 25 / 49 / 81 个格点。
- 格点只存在于整数坐标处，不存在格心点；星点只能落在格点上。
- 星域有边界，**越界即非法**：镜像落点若超出 `0 ≤ x,y ≤ N-1`，该源点在本关不可镜像（关卡校验会禁止这种源点出现在正式关里，只有残星例外，见 §3.9）。

### 2.2 坐标约定

- 坐标写作 `(x, y)`：`x` 向右递增，`y` **向下**递增（屏幕坐标，origin 在左上角）。
- 一格 = 1 单位。星域四角为 `(0,0)`、`(N-1,0)`、`(0,N-1)`、`(N-1,N-1)`。
- 内部统一用整数索引，禁止用像素做逻辑运算（像素只在渲染层出现一次，见技术方案 §4.2）。

### 2.3 点、方向与键

- 普通关：一个星点 = `(x, y)`。
- 箭头关（第七章起）：一个星点 = `(x, y, d)`，`d ∈ {U, R, D, L}` 表示箭尾朝向（上/右/下/左）。
- 一格最多一个星点：**同一格不允许出现两个点，也不允许同格异向**。
- 点的唯一键：普通关 `"x,y"`；箭头关 `"x,y,d"`。判定以键的集合比较，绝不以浮点距离比较。

### 2.4 七类对称规格

关卡数据里的 `sym` 字段描述对称关系，共七类：

| 类型 | 语义 | 参数 | 点变换公式 |
|---|---|---|---|
| `v` | 竖直轴 | `axis`（整数=整格轴，半整数=缝轴） | `(x, y) → (2a − x, y)` |
| `h` | 水平轴 | `axis`（同上） | `(x, y) → (x, 2b − y)` |
| `d1` | 45° 主对角（↘） | `c`（**必须是整数**） | 关于直线 `y = x + c` 翻折：`(x, y) → (y − c, x + c)` |
| `d2` | 45° 副对角（↗） | `c`（**必须是整数**） | 关于直线 `x + y = c` 翻折：`(x, y) → (c − y, c − x)` |
| `p` | 中心对称 | `cx, cy`（整数或半整数） | `(x, y) → (2cx − x, 2cy − y)` |
| `cross` | 双轴十字 | `ax, ay`（各自整数或半整数） | 群作用 4 个像：`(x,y)`、`(2ax−x, y)`、`(x, 2ay−y)`、`(2ax−x, 2ay−y)` |
| `r` | 四重旋转（第八章） | `cx, cy`（整数或半整数，且**中心必须落在格点或格心**：`hx+hy` 为偶数） | 绕中心顺时针 90°/180°/270°：`(x,y) → (cx−(y−cy), cy+(x−cx))` 及其迭代 |

**群阶 k**：`v / h / d1 / d2 / p` 的 k = 2；`cross` 与 `r` 的 k = 4。目标点数恒等于 `源点数 × (k − 1)`（这是关卡校验的硬性断言）。

### 2.5 整格轴与缝轴

同一条轴线有两种合法摆法，二者判定规则不同，必须由关卡数据显式指定：

| 摆法 | 参数 | 表现 | 轴上格点 |
|---|---|---|---|
| **整格轴** | `axis = 3` | 轴线正好穿过第 3 列（或行）的格点 | 该列格点成为**轴格**：被「星尘轨」覆盖，**不可落点，也不参与判定** |
| **缝轴** | `axis = 2.5` | 轴线走在第 2 与第 3 列之间的缝隙 | 没有任何格点落在轴上，所有格点都可落点 |

- 整格轴的意义：轴线是「镜子」，镜子上的格子被占住，避免「轴上的点算不算自对称」的口径争议。
- 缝轴的意义：让「离轴最远的边缘点」翻折后直接越界，天然形成残星素材（第六、十章使用），同时避免轴格留白。
- **斜轴（d1/d2）的 `c` 只允许整数**：因为 `(x,y) → (y−c, x+c)`，若 `c` 为半整数，像会落在半格上，星点无法吸附到格点。中心 `p`、双轴 `cross` 与旋转 `r` 允许半整数中心（此时无轴格）。`r` 还额外要求中心落在格点或格心，否则格点转过去会落到半格。

### 2.6 轴格（仅整格轴存在）

- 整格轴 `v: a` → 轴格集合 `{(a, y) | 0 ≤ y < N}`；`h: b` → `{(x, b)}`。
- `d1: c` → `{(x, x+c) | 0 ≤ x+c < N}`；`d2: c` → `{(x, c−x)}`。
- `p` 的整格中心 `(cx,cy)` 只有 1 个轴格（「星核」）；`r` 的整格中心同样只有 1 个轴格（「旋核」）；`cross` 的整格轴格是两整条行列。
- 规则：**轴格永不可落点，也永不参与判定**。关卡校验保证源点与目标都不落在轴格上。

## 3. 核心规则（细化到可实现）

### 3.1 源点、残星与玩家点

关卡给玩家看的点分两种，数据里用两个数组区分，**不再靠颜色临时猜**：

- **源点 `sources`**：必须被镜像的真点。轴一侧（多轴关是某一个象限）给出，通常 2~8 个。
- **残星 `strays`**：故意不对称的干扰点，**永不参与对称**。数量 0~3，只在第六章及以后出现。
- **暗域 `blocked`**：禁落格，玩家点上去会被弹回；它**不参与对称、永远不是目标**。数量 0~6，只在第九章及以后出现。

玩家自己放的点叫**玩家点 `placed`**，只存在于玩家点集 P 里。

### 3.2 操作规则

| 操作 | 规则 |
|---|---|
| 落点 | 点击空格点 → 放一颗星。**自动吸附到最近格点**：触点距该格点 ≤ `0.6 × 格距` 才算命中，超出视为点空（不落点，仅轻微抖动反馈） |
| 撤点 | 点击已有玩家星 → 移除（仅玩家点；源点与残星不可移除） |
| 撤销 | 撤销上一步玩家操作，可无限次，不计失误 |
| 清空 | 移除全部玩家点，不计失误 |
| 落点范围 | 任意非轴格、非已占用的格点都可落点（包括给定侧的空格）；但落在给定侧的空格在判定时算「多余点」，会判偏差 |
| 箭头关 | 底部出现方向盘（上下左右四键）：点击空格按当前方向落点；点击已有玩家箭头 → 顺时针旋转 90°；长按 → 删除。默认方向为「朝向轴线」 |
| 提交 | 随时可提交；玩家点为 0 时按钮置灰 |

### 3.3 判定规则（唯一权威定义）

设关卡源点集 `S`、对称群 `G`（阶 k）、玩家点集 `P`。

1. **目标集** `T = { g(p) | p ∈ S, g ∈ G, g(p) ≠ p }`，其中 `g(p)` 计入时要求：落在星域内、不是轴格、且不与其它像重合（后三条由关卡校验保证）。
2. **缺点** `M = T \ P`（应补未补的点）。
3. **多点** `E = P \ T`（多放的点）。
4. **通过** ⟺ `M = ∅` 且 `E = ∅`（严格集合相等，没有任何容差）。
5. **偏差数** `D = |M| + |E|`，仅用于「偏差 n 处」的计数展示；高阶关可关闭该计数（见 §3.4）。
6. **残星永不参与判定**：既不产出目标，也不会因为「你没镜像它」而扣分；但玩家若主动把残星镜像了，那个点属于 `E`，会判多点。
7. **轴格永不参与判定**（见 §2.6）。
8. 判定函数只向 UI 返回 `{ pass: boolean, deviations: number }`；`M`、`E` 的坐标数组仅供调试与提示系统内部使用，**不得渲染到界面**（这是本玩法「不定位」原则的技术保证）。
9. **暗域格永不参与判定**：可落点集合 = 板内格点 − 轴格 − 暗域格；目标集不含暗域格（关卡校验保证），玩家也不可能在暗域落点。
10. **同一格不得有两个方向目标**：箭头关若同一格点需要两个不同方向，玩家永远补不出来，关卡校验直接判错。

### 3.4 反馈展示

| 关卡配置 | 失败时展示 |
|---|---|
| `showMismatch: true`（教学 ~ 前 4 章） | 「星轨错位 · 偏差 n 处」 |
| `showMismatch: false`（第 5 章起的高阶关） | 仅「星轨错位」，不给数量 |

- 通过：整幅星图亮起，源点与镜像点之间连出发光线（「星座连线」），顶部「星轨对齐」。
- 失败：星域轻微晃动 200ms + 顶部提示条，**不闪烁任何具体格点**。
- 无论通过或失败，历史提交只记录「第几次 · 结果 · 偏差数」（若开启计数）。

### 3.5 提交次数、失败与重开

| 项 | 规则 |
|---|---|
| 提交上限 `moves` | 每关独立配置：教学关 99（等于不限），常规关 3~9。`moves` 是**提交次数**，不是落点次数 |
| 次数用尽未通过 | 本关失败：弹出「星图崩解」，给出「重新观测（重开本关）」「返回星图册」 |
| 重开 | 清空玩家点、失误数、提示用量与计时；**关卡布局不变**（同一关的图形是固定的，重开只是重做） |
| 无时间限制 | 计时只用于记录成绩与成就，不参与判定与失败判定 |
| 中途退出 | 不保存玩家点，视为放弃，不计失败次数 |

### 3.6 星级

`starOf(mistakes, hintsUsed)`：

| 星级 | 条件 |
|---|---|
| ★★★ | `mistakes = 0` 且 `hintsUsed = 0`（首次提交即通过、全程零提示） |
| ★★ | `mistakes ≤ 2` 且 `hintsUsed ≤ 1`（含「零失误但用过 1 次提示」） |
| ★ | 其余通关情形 |

- `mistakes` = 被判偏差的提交次数（不是偏差点数）。
- 星级只记录历史最好成绩；刷新页面、重开、重进都不降级。
- 关卡列表显示 0~3 颗星；章节页显示该章星数合计。

### 3.7 提示系统

- 每关 `hints` 次（教学关 2 次，其余 1 次）。
- 触发：玩家主动点「提示」（无冷却、无前置条件）。
- 内容：从当前 `M` 中随机取一个未补的点，**高亮其源点 2 秒**并在目标格点显示脉冲虚影 3 秒（虚影不落点，仍需玩家自己确认位置）。
- 特殊情形：若 `M` 为空（玩家已填满但有多点），提示改为高亮一个 `E` 中的多余点。
- 代价：消耗一次提示；`hintsUsed > 0` 时最高只能 2 星。
- 次数用尽：按钮置灰，文案「本关提示已用尽」。

### 3.8 翻折预览（辅助，P1）

- 长按任意源点 400ms：在它的镜像格点显示一颗半透明幽灵星，松手消失。
- 不消耗提示、不降星，仅在**教学关 1~3 与帮助页**默认开启；可在设置里全局关闭（默认开）。
- 目的：把「翻折」从抽象运算降为可观察的辅助线，降低首关劝退率。

### 3.9 残星机制（第六章）

- 残星是「故意不对称」的点，规则上**不参与任何对称要求**。
- 视觉必须与真源点**形状不同**，不能只靠亮度：真星为**实心 + 四芒辉光**；残星为**冷青实线细环 + 缓慢漂移**（与暗域的紫色虚线暗斑在颜色、形状上都不同，色盲用户也可靠形状区分）。
- 陷阱机制：残星的镜像格点在板内且为空，**看起来「就该补」**。玩家若把它镜像，会多放一个点 → 判 `E` → 偏差。
- 关卡校验硬约束：每颗残星必须满足「镜像格在板内、不在目标集、不与源点或其他残星冲突」，否则这颗残星不构成有效陷阱，视为关卡数据错误。
- 首次出现（第 31 关）：强制引导浮层「暗色空心的星是残星，它们不参与对称，不要替它们补点」；长按残星显示标签「残星」。
- P2 变体「无标记残星」：不区分外观，靠「本关需补 n 点」的计数约束反推哪几颗是残星；需要额外的唯一性校验，首期不做。

### 3.10 箭头变体（第七章）

- 每个点是「带尾巴的星」，方向 `d ∈ {U, R, D, L}`，翻折后方向必须一起翻转。
- 方向变换只看翻折的**线性部分**（位移不改变方向）：

| 对称 | U | R | D | L |
|---|---|---|---|---|
| `v`（竖直轴） | U | L | D | R |
| `h`（水平轴） | D | R | U | L |
| `d1`（y = x + c） | L | D | R | U |
| `d2`（x + y = c） | R | U | L | D |
| `p`（中心 180°） | D | L | U | R |
| `r`（顺时针 90°） | R | D | L | U |

- **双轴 `cross` 要逐像取表**：一个源点的四个像分属「竖镜像 / 横镜像 / 180°」三个不同的变换，方向必须按各自那一行算。例如源点 `U`：竖镜像后仍是 `U`，横镜像后变 `D`，180° 后变 `D` —— 只算一次方向会把三个目标全算错。
- 判定键包含方向：`"x,y,d"`。**位置对但方向错** → 该目标计 1 个缺点 + 该玩家点计 1 个多点，偏差数 +2（这也是为什么高阶关不给偏差数）。
- 一格只能有一个箭头，方向不作独立图元；四重旋转关的 180° 与 270° 两像方向分别为 `D/L/U/R` 与 `L/U/R/D`，必须逐像套表。

### 3.11 中心对称与双轴（第四、五章）

- **中心对称**：绕 `(cx, cy)` 旋转 180°，`(x,y) → (2cx−x, 2cy−y)`。整格中心时中心格为「星核」不可落点。
- **双轴十字**：竖轴 + 横轴同时对称，一个源点产出 3 个目标（另外三个象限各一个）；双整格轴时两条轴线上的整行整列都不可落点。
- 玩家不需要理解「群论」，只需要理解「一个点要同时翻竖轴和横轴，所以另外三个角各要一颗」；帮助页用一张四象限图示说明。

### 3.12 边界与非法输入（必须实现）

| 情形 | 处理 |
|---|---|
| 点击轴格 | 不落点，提示「轴上的格点不能落星」（轻提示，不扣分） |
| 点击暗域格 | 不落点，提示「暗域里落不下星」，与轴格的区别只在文案 |
| 点击已占用格 | 若是玩家点 → 移除；若是源点/残星 → 不动 |
| 触点距最近格点 > 0.6 格距 | 忽略，不吸附 |
| 提交时玩家点为 0 | 按钮禁用 |
| 关卡数据缺失/损坏 | 进入游戏页失败兜底页「星图数据损坏」，提供返回 |
| 进度存储损坏 | 按空进度处理，不崩溃 |
| 箭头同格改向 | 只允许顺时针循环，不产生两个点 |

### 3.13 四重旋转（第八章「星旋」）

- 整张星图绕中心顺时针转 90° 后必须与原来完全一致，等价于群 `C4 = { e, r90, r180, r270 }`。
- 一个源点产出 3 个目标（右、下、左），四颗星连起来是一个绕中心的方环；比双轴更「绕」，因为没有可以对照的直线。
- 中心落在格点上时，中心格是唯一不动点，视同轴格不可落点（「旋核」）；中心落在格心时没有死点，所有格点都能参与。
- 视觉上不画轴线，改画金色虚线圆环 + 三枚缓慢自转的曳光点；玩家一眼能看出「这里是转，不是翻」。
- 难度来源：玩家容易把 90° 当成 180°，或漏掉「转三圈才回到原位」。教学关（41）只放 2 个源点、9 次提交，先把「右→下→左」的顺序建立起来。

### 3.14 暗域禁落格（第九章「暗域」）

- 星图上出现 2~6 个带虚线边框的暗斑格（`blocked`），这些格子落不下星，点击会被弹回。
- 暗域**不是目标、也不是残星**：它只负责「占位挡路」，让原本一目了然的行列数格子被打断，制造「明明该在那儿、却放不下去」的错觉。
- 关卡校验硬约束：暗域不得压源点、目标、残星或轴格；暗域不能把可用格点挤到装不下「源点+目标」。
- 暗域与各种对称混合出现：竖轴挡在轴两侧、副对角挡住两条斜线、旋转关压住四条中心线。终章再与残星、箭头叠加，形成「先辨认机制、再算坐标」的双层负担。
- 视觉：吞光的暗斑 + 虚线边框 + 中间一枚暗核，与轴格的暖金、残星的灰蓝在明度与形状上都拉开。

### 5.3 交互流程状态机

```
LOADING → PLAYING ⇄ CHECKING → WON / FAILED
                 ↑                 │
                 └──── 重开/下一关 ─┘
```

| 状态 | 可做 | 不可做 |
|---|---|---|
| `PLAYING` | 落点、撤点、撤销、清空、提示、提交 | — |
| `CHECKING`（400ms） | 无 | 全部锁定，防连点重复提交 |
| `WON` | 下一关、返回、看连线 | 继续落点 |
| `FAILED` | 重开、返回 | 继续落点 |

### 5.4 关键交互细则

- **提交反馈节奏**：点击提交 → 按钮变「校准中…」→ 400ms 后出结果（留出「屏息」感，避免闪光过快）。
- **通过**：先所有目标点亮起，再逐条画源点→镜像的连线（每 80ms 一条），最后顶部出现「星轨对齐」与星级。
- **失败**：整块星域 200ms 左右晃动 2 次；顶部条显示「星轨错位」；不改变任何已放点的位置（玩家可继续修改后再次提交，若还有次数）。
- **提示高亮**：源点外圈脉冲环 + 目标格半透明幽灵；3 秒后自动消失，可重复点（继续消耗）。
- **剩余次数**：HUD 显示「提交 n / m 次」（已提交数 / 上限）；`moves = 99` 时显示「提交 n 次 · 不限」，避免出现「n / 99」的怪数字。
- **返回确认**：有未提交的玩家点时，返回弹「当前进度不保存，确定离开？」。

### 5.5 空态与异常态

| 场景 | 表现 |
|---|---|
| 首次进入（进度空） | 只有第 1 关可点，其余锁形图标 |
| 关卡数据加载失败 | 居中「星图数据损坏」+ 返回按钮 |
| 本地存储不可用（隐私模式） | 仍可玩，退出即丢进度，顶部一次性 toast「进度无法保存」 |
| 切后台再回来 | 保留当前玩家点与计时（`onHide` 记时间差，`onShow` 折回） |

### 6.4 关卡数据规则（设计侧硬约束）

1. `id` 从 1 连号到 64，章节 1~10，关卡不跳号；第 8/9/10 章分别 7/8/9 关。
2. `sources` 全部在板内、不在轴格、不在暗域、互不重复。
3. `targets`（构建期推导）全部在板内、不在轴格、不在暗域、互不重复、不与源点重合。
4. 目标点数必须等于 `sources.length × (k−1)`。
5. `strays` 不在 `sources`、`targets`、`blocked` 中；每颗残星的镜像格必须在板内且为空（否则不构成陷阱，判数据错误）。
6. `blocked` 只在第九章及以后出现，0~6 格；不得压源点、目标、残星、轴格，且不得让「源点+目标」超过可用格点（板面 − 轴格 − 暗域）。
7. `r` 的中心必须落在格点或格心（`hx+hy` 为偶数）；整格中心的那一格是死点，不能落源点。
8. 箭头关同一格点不得出现两个不同方向的目标。
9. `moves ≥ 1`，`hints ∈ {1,2}`，`board ∈ {5,7,9}`，`d1/d2` 的 `c` 为整数，`axis` 为整数或半整数。
10. 可放置空格数（板面 − 轴格 − 暗域）必须 ≥ `sources.length + targetCount`，避免无解。

### 6.5 已校验的四个基准关（用于开发自测）

**第 1 关（竖轴，5×5，`v:2`）**

- 源点 `(0,4)`、`(1,1)` → 目标 `(4,4)`、`(3,1)`；轴格为整列 `x=2`。

**第 14 关（斜轴，7×7，`d1: c=0`，即 `y=x`）**

- 源点 `(1,6)`、`(0,1)`、`(2,4)`、`(0,3)` → 目标 `(6,1)`、`(1,0)`、`(4,2)`、`(3,0)`。

**第 25 关（双轴，7×7，`cross 3/3`）**

- 源点 `(0,1)` → 目标 `(0,5)`、`(6,1)`、`(6,5)`；源点 `(2,0)` → `(4,0)`、`(2,6)`、`(4,6)`；源点 `(2,2)` → `(4,2)`、`(2,4)`、`(4,4)`；共 9 个目标。

**第 31 关（残星，7×7，`v:3`）**

- 真源点 `(2,5)`、`(0,3)`、`(1,0)` → 目标 `(4,5)`、`(6,3)`、`(5,0)`。
- 残星 `(1,6)`、`(2,2)`：镜像格 `(5,6)`、`(4,2)` 必须保持为空；误补即判多点。

**第 41 关（四重旋转，5×5，`r (2,2)`）**

- 源点 `(1,0)`、`(0,1)` → 目标 `(4,1)`、`(3,4)`、`(0,3)`、`(3,0)`、`(4,3)`、`(1,4)`；中心格 `(2,2)` 是死点。

**第 44 关（格心旋转，7×7，`r (2.5,2.5)`）**

- 没有轴格；源点 `(0,0)` 转出 `(5,0)`、`(5,5)`、`(0,5)`，刚好是 6×6 内框的四个角。

**第 48 关（暗域，7×7，`v:3` + 暗域）**

- 源点 `(0,2)`、`(2,5)`、`(0,0)`、`(2,0)` → 目标 `(6,2)`、`(4,5)`、`(6,0)`、`(4,0)`。
- 暗域 `(1,3)`、`(5,3)` 夹在轴两侧，既不参与判定，也不在目标集里。

**第 56 关（旋转 + 箭头，7×7，`r (3,3)`）**

- 源点 `(2,0,U)` → `(6,2,R)`、`(4,6,D)`、`(0,4,L)`；源点 `(1,1,R)` → `(5,1,D)`、`(5,5,L)`、`(1,5,U)`。方向随每次 90° 一起转。
